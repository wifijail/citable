# Citable — запуск и настройка (пошагово, на русском)

Этот файл — для владельца сайта: как задеплоить, где хранятся данные, куда вписать свои
данные, как принимать оплату без Stripe и Lemon Squeezy и что нужно сделать по законам Казахстана.

> Главное правило: **секреты и реквизиты не пишутся в код.** Всё задаётся переменными
> окружения в Vercel (Settings → Environment Variables). После изменения переменных —
> **Deployments → последний деплой → ⋯ → Redeploy** (переменные `NEXT_PUBLIC_*`
> вшиваются в сайт при сборке).

## 1. Деплой

1. `git push` — Vercel соберёт проект сам.
2. Файл `vercel.json` включает ежедневную очистку старых данных (`/api/cron/cleanup`).
   На бесплатном тарифе Vercel разрешён один запуск в день — этого достаточно.
   Можно задать `CRON_SECRET` (любая длинная строка) — Vercel сам подставит его в запрос.

## 2. База данных

Без `DATABASE_URL` данные живут в памяти сервера и пропадают при перезапуске.

**Важно для Казахстана.** Закон «О персональных данных и их защите» (ст. 12) требует хранить
персональные данные в базе **на территории РК**. Neon/Supabase — серверы за границей.
Варианты:
- для запуска и тестов — Neon через Vercel (Storage → Neon), понимая риск;
- для работы с реальными клиентами — Postgres у казахстанского провайдера (ps.kz, Kazakhtelecom
  Cloud, Hoster.kz и др.) и его строка подключения в `DATABASE_URL`.

Место хранения укажите в `NEXT_PUBLIC_DATA_LOCATION` — оно выводится в Политике конфиденциальности.

Что хранится:

| Таблица | Что внутри | Сколько хранится |
|---|---|---|
| `scans` | адрес, оценка, отчёт; хэш IP | отчёт 365 дней, хэш IP 48 часов |
| `leads` | почта из формы «сообщить об открытии оплаты» + отметка согласия | 730 дней |
| `contact_messages` | сообщения из формы (имя необязательно) + согласие | 730 дней |
| `payment_requests` | заявки «я оплатил» + согласие | отклонённые — 90 дней |
| `checkouts` | незавершённые оплаты Stripe/LS | 30 дней |
| `licenses` | ключи, тариф, статус, срок | пока нужны |

Удаление данных человека по запросу: админка → «Удалить данные человека» (по email).

## 3. Секреты и админка

| Переменная | Значение |
|---|---|
| `LICENSE_SECRET` | длинная случайная строка (64 символа). Не меняйте после начала продаж |
| `ADMIN_PASSWORD` | пароль админки, от 10 символов |

В админке: чек-лист настройки, **оплаты на проверке** (подтвердить/отклонить), выдача ключа
вручную, продление на 31 день, отзыв ключа, удаление данных по email, заявки, сообщения, проверки.

## 4. Приём оплаты без Stripe и Lemon Squeezy

Сайт поддерживает два способа. Работает первый настроенный (или задайте `PAYMENT_PROVIDER`).

### Способ A — Gumroad (рекомендую, доступ открывается автоматически)
Gumroad сам принимает карту покупателя, сам считает налоги покупателя (он «merchant of record»)
и выплачивает деньги продавцу. В октябре–ноябре 2024 Gumroad объявил о выплатах
в Казахстан. **Перед регистрацией проверьте актуальные условия выплат для KZ в их справке** —
в интернете есть жалобы на возвраты банковских переводов, тогда пробуйте PayPal-выплату.

1. Зарегистрируйтесь на gumroad.com, заполните данные для выплат.
2. Создайте 3 продукта: Pro (membership, $7/мес), Agency (membership, $19/мес), Lifetime ($49).
3. В каждом продукте включите **«Generate a unique license key per sale»**.
4. Скопируйте **product_id** (виден в блоке License key у продукта) и публичную ссылку продукта.
5. В Vercel:
   `GUMROAD_PRODUCT_ID_PRO`, `GUMROAD_URL_PRO`, `GUMROAD_PRODUCT_ID_AGENCY`, `GUMROAD_URL_AGENCY`,
   `GUMROAD_PRODUCT_ID_LIFETIME`, `GUMROAD_URL_LIFETIME`.
6. Redeploy → `/api/health` должно показать `"payments": "gumroad"`.

Как это работает: покупатель платит на Gumroad → получает ключ от Gumroad → вставляет его под
сканером → сайт проверяет ключ через публичный API Gumroad (`/v2/licenses/verify`) и раз в 6 часов
перепроверяет: возврат, спор, неоплата или конец подписки — доступ закрывается сам.
Номер телефона и ваши карты на сайте не светятся.

### Способ B — любая ссылка на оплату (Boosty, Patreon, Tribute…)
1. Создайте на платформе уровни подписки / товар.
2. В Vercel: `PAYMENT_PLATFORM_NAME=Boosty`, `PAYMENT_LINK_PRO`, `PAYMENT_LINK_AGENCY`,
   `PAYMENT_LINK_LIFETIME` (только https), плюс `LICENSE_SECRET`.
3. Покупатель платит на платформе → возвращается и отправляет форму «Я оплатил(а)»
   (почта + ник на платформе) → вы видите заявку в админке, находите платёж в кабинете платформы
   → «Подтвердить и выдать ключ». Ключ появляется у покупателя на странице статуса.
4. Помесячные тарифы выдаются на 31 день; когда подписка на платформе продлилась —
   кнопка «+31 день» в таблице лицензий.

Про платформы честно:
- **Boosty** — по найденным данным выплаты в долларах/евро на карты с комиссией; условия для
  авторов из Казахстана я не нашёл официально — уточните в поддержке Boosty до запуска.
- **Patreon** — Казахстан есть в списке стран для выплат через PayPal (по справке Patreon);
  у PayPal в Казахстане есть ограничения на приём — проверьте свой аккаунт.
- **Tribute** (Telegram) — выплаты в рублях/евро/крипте; условия для KZ уточняйте.
- **Paddle** — поддерживает продавцов из Казахстана, но требует проверки сайта и интеграции.
- После регистрации ИП — локальные эквайринги (Kaspi Pay, Freedom Pay, CloudPayments KZ).

### Цены в тенге
Закон о защите прав потребителей РК (ст. 25) требует указывать стоимость в тенге.
Задайте `NEXT_PUBLIC_PRICE_KZT_PRO` / `_AGENCY` / `_LIFETIME` — рядом с долларами появится «≈ N ₸».

## 5. Ваши данные на сайте

| Переменная | Пример |
|---|---|
| `NEXT_PUBLIC_LEGAL_ENTITY_NAME` | `ИП Иванов Иван Иванович` |
| `NEXT_PUBLIC_LEGAL_REG_NUMBER` | ИИН/БИН |
| `NEXT_PUBLIC_LEGAL_REG_DETAILS` | `Уведомление о начале деятельности ИП от …` |
| `NEXT_PUBLIC_LEGAL_ADDRESS` | адрес регистрации ИП |
| `NEXT_PUBLIC_CONTACT_EMAIL` | почта поддержки |
| `NEXT_PUBLIC_CONTACT_PHONE` | телефон (можно отдельный рабочий номер) |
| `NEXT_PUBLIC_DATA_LOCATION` | `Казахстан, Алматы (ps.kz)` |
| `NEXT_PUBLIC_REFUND_DAYS` | `14` |

Пустые поля просто не показываются — предупреждений на публичных страницах больше нет.
Недостающие поля видны только вам — в чек-листе админки.

## 6. Почта (Resend) — по желанию
`RESEND_API_KEY`, `EMAIL_FROM`, `OWNER_EMAIL`. Тогда: ключ приходит покупателю письмом,
вам — уведомления о сообщениях и заявках на оплату, покупателю — письмо при отклонении.
