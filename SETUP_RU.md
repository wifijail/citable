# Citable — запуск и настройка (пошагово, на русском)

Этот файл — для владельца сайта. Здесь по шагам: как задеплоить, где хранятся данные,
куда вписывать свои контакты и реквизиты, как подключить оплату и почту.

> Главное правило: **секреты и реквизиты не пишутся в код.** Всё задаётся переменными
> окружения в Vercel (Settings → Environment Variables). Код лежит на GitHub публично
> или приватно — неважно, ваши ключи туда не попадают.

---

## 0. Что где лежит

| Что | Где |
|---|---|
| Ваши контакты, название компании, юр. данные | Переменные `NEXT_PUBLIC_CONTACT_*`, `NEXT_PUBLIC_LEGAL_*` (или файл `src/config/site.ts`) |
| Цены, которые показываются на сайте | `src/lib/plans.ts` |
| Тексты сайта на 4 языках | `src/i18n/ui/en.ts`, `ru.ts`, `es.ts`, `de.ts` |
| Тексты юридических страниц | `src/i18n/legal.ts` |
| Логотип и иконки | `src/components/ui/logo.tsx`, `src/app/icon.tsx`; ваш исходный пакет — `public/brand/original-favicon/` |
| Данные (проверки, заявки, сообщения, лицензии) | База Postgres (`DATABASE_URL`) |
| Просмотр данных и выдача ключей | `https://ваш-домен/ru/admin` |
| Проверка, что всё подключено | `https://ваш-домен/api/health` |

## 1. Деплой на Vercel

1. Отправьте код на GitHub (`git push`). Vercel сам начнёт сборку.
2. Если проект в Vercel уже создан — ничего делать не нужно, новый коммит задеплоится.
   Если нет: [vercel.com/new](https://vercel.com/new) → Import → `wifijail/citable` → Deploy.
3. Сайт соберётся **даже без единой переменной**. Но без базы данные теряются, а без
   `LICENSE_SECRET` не работает оплата — поэтому дальше шаги 2–4.

После каждого изменения переменных: **Deployments → последний деплой → ⋯ → Redeploy**.
Переменные применяются только к новым сборкам.

### Если сборка упала
Откройте деплой → **Build Logs** → найдите красные строки. Частые причины:
- `Invalid URL` — была в первой версии (пустой `NEXT_PUBLIC_SITE_URL`), **исправлено**.
- `Type error` / `Module not found` — ошибка в коде; локально её покажет `npm run build`.

## 2. База данных (обязательно для реальных клиентов) — бесплатно

Вариант через Vercel (проще всего):

1. В проекте на Vercel: **Storage → Create Database → Neon (Postgres) → Continue**.
2. Выберите регион ближе к пользователям (например, Frankfurt), план **Free**.
3. Подключите базу к проекту `citable` для окружений **Production** и **Preview**.
   Vercel сам добавит переменную `DATABASE_URL`.
4. Redeploy.

Таблицы создаются **автоматически** при первом запросе — ничего запускать не нужно.
Проверка: откройте `/api/health` — должно быть `"database": "ok"`.

Что хранится в базе:

| Таблица | Что внутри |
|---|---|
| `scans` | каждая проверка: адрес, оценка, полный отчёт (для ссылок «поделиться») |
| `leads` | почты, оставленные в форме «пришлём отчёт» и в листе ожидания |
| `contact_messages` | сообщения из формы «Контакты» |
| `checkouts` | начатые оплаты (связка «покупатель ↔ платёж») |
| `licenses` | проданные и выданные вручную ключи, их статус и срок |

IP-адреса **не хранятся** — только необратимый хэш для лимита бесплатных проверок.

## 3. Секреты и админ-панель

В Vercel → Settings → Environment Variables добавьте:

| Переменная | Значение |
|---|---|
| `LICENSE_SECRET` | длинная случайная строка (сгенерировать: `openssl rand -hex 32` или любой генератор паролей на 64 символа) |
| `ADMIN_PASSWORD` | ваш пароль от админки, не короче 10 символов |

⚠️ `LICENSE_SECRET` задайте **один раз** и не меняйте: при смене все проданные ключи
перестанут работать.

Админка: `https://ваш-домен/ru/admin`. В ней:
- чек-лист «что подключено, а что нет»;
- статистика: проверки, заявки, сообщения, активные лицензии, примерный MRR;
- таблицы заявок (с выгрузкой в CSV), сообщений, лицензий, последних проверок;
- **ручная выдача ключа** — для оплат переводом/по счёту и подарков;
- отзыв ключа.

## 4. Ваши контакты и юридические данные

Без них страницы «Контакты» и «Условия» пустые, а платёжные системы **не одобрят магазин**.

| Переменная | Пример |
|---|---|
| `NEXT_PUBLIC_CONTACT_EMAIL` | `support@вашдомен.com` |
| `NEXT_PUBLIC_CONTACT_TELEGRAM` | `citable_support` (без @) |
| `NEXT_PUBLIC_CONTACT_SOCIAL_URL` | ссылка на X / LinkedIn / сайт |
| `NEXT_PUBLIC_CONTACT_RESPONSE_TIME` | `24 часа` |
| `NEXT_PUBLIC_LEGAL_ENTITY_NAME` | название компании, ИП или ваше ФИО |
| `NEXT_PUBLIC_LEGAL_COUNTRY` | страна, по законам которой действуют условия |
| `NEXT_PUBLIC_LEGAL_ADDRESS` | адрес (необязательно) |
| `NEXT_PUBLIC_LEGAL_REG_NUMBER` | рег. номер / ИНН (необязательно) |
| `NEXT_PUBLIC_REFUND_DAYS` | `14` — срок возврата денег |

Пока эти поля пустые, на юр. страницах показывается жёлтое предупреждение «это шаблон»,
а вместо данных — заметные `‹плейсхолдеры›`. Ничего не выдумывается.

Тексты условий — **шаблон, а не юридическая консультация**. Перед приёмом денег их
стоит показать юристу своей страны.

## 5. Приём оплаты

### Куда вводятся реквизиты (карта / счёт)?
**Не на сайте.** Банковские реквизиты для выплат вы указываете в личном кабинете
платёжного сервиса (Lemon Squeezy или Stripe). Сайт получает от сервиса только API-ключи,
создаёт страницу оплаты и узнаёт об успешном платеже через webhook. Данные карт
покупателей сайт никогда не видит.

### ⚠️ Важно про страну
Stripe и Lemon Squeezy работают не во всех странах. Перед регистрацией **проверьте
список поддерживаемых стран** в их документации. В частности, продавцам, зарегистрированным
в России, эти сервисы сейчас, как правило, недоступны. Если ваша страна не поддерживается:
- можно работать через компанию/ИП в поддерживаемой стране;
- или принимать оплату иначе (перевод, счёт) и **выдавать ключи вручную в админке** —
  эта функция сделана как раз для такого случая.

### Вариант A — Lemon Squeezy (рекомендую)
Lemon Squeezy — «merchant of record»: он сам юридически продаёт товар и сам платит
налоги (НДС) по всему миру. Для одиночного основателя это снимает главную головную боль.

1. Зарегистрируйтесь на [lemonsqueezy.com](https://www.lemonsqueezy.com), создайте магазин,
   заполните данные для выплат.
2. **Products → New product**, создайте три товара:
   - **Pro** — подписка, $7 / месяц
   - **Agency** — подписка, $19 / месяц
   - **Lifetime** — разовая оплата, $49
3. У каждого товара скопируйте **Variant ID** (в настройках варианта).
4. **Settings → API → Create API key** → скопируйте ключ.
5. **Settings → Stores** → скопируйте Store ID (число).
6. **Settings → Webhooks → +**:
   - URL: `https://ваш-домен/api/webhooks/lemonsqueezy`
   - Signing secret: придумайте строку (её же впишете в Vercel)
   - События: `order_created`, `order_refunded`, `subscription_created`,
     `subscription_updated`, `subscription_cancelled`, `subscription_resumed`,
     `subscription_expired`, `subscription_paused`, `subscription_unpaused`
7. В Vercel добавьте:
   `LEMONSQUEEZY_API_KEY`, `LEMONSQUEEZY_STORE_ID`, `LEMONSQUEEZY_WEBHOOK_SECRET`,
   `LEMONSQUEEZY_VARIANT_PRO`, `LEMONSQUEEZY_VARIANT_AGENCY`, `LEMONSQUEEZY_VARIANT_LIFETIME`.
8. Redeploy. Проверьте `/api/health` → `"payments": "lemonsqueezy"`.
9. Сделайте тестовую покупку в **Test mode** Lemon Squeezy.

### Вариант B — Stripe
1. [dashboard.stripe.com](https://dashboard.stripe.com) → Products → создайте те же три
   цены (две recurring, одну one-time), скопируйте **Price ID** (`price_…`).
2. Developers → API keys → **Secret key**.
3. Developers → Webhooks → Add endpoint:
   - URL: `https://ваш-домен/api/webhooks/stripe`
   - События: `checkout.session.completed`, `checkout.session.async_payment_succeeded`,
     `customer.subscription.updated`, `customer.subscription.deleted`, `charge.refunded`
   - Скопируйте **Signing secret** (`whsec_…`).
4. В Vercel: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_PRO_MONTHLY`,
   `STRIPE_PRICE_AGENCY_MONTHLY`, `STRIPE_PRICE_LIFETIME`.

### Как работает покупка (чтобы понимать, что происходит)
1. Клиент жмёт «Подключить Pro» → сайт создаёт страницу оплаты у провайдера.
2. Клиент платит → провайдер присылает webhook → сайт создаёт лицензию в базе.
3. Клиента возвращает на `/checkout/success` → он сразу видит ключ, ключ сохраняется
   в его браузере и (если настроена почта) приходит письмом.
4. Отмена подписки → доступ работает до конца оплаченного периода.
   Возврат денег или окончание подписки → ключ перестаёт открывать платные функции.

Пока оплата не подключена, кнопки тарифов **не ломаются**: открывается окно
«Оплата настраивается» с формой почты и ссылкой на контакты.

### Если меняете цены
Цена на сайте — `src/lib/plans.ts`. Цена, которую реально спишут, — в кабинете
провайдера. Меняйте **в обоих местах**.

## 6. Почта (Resend) — необязательно, но желательно

1. [resend.com](https://resend.com) → зарегистрируйтесь → **Domains → Add domain** →
   добавьте DNS-записи у регистратора домена → дождитесь Verified.
2. **API Keys → Create** → скопируйте.
3. В Vercel: `RESEND_API_KEY`, `EMAIL_FROM` (например `Citable <hello@вашдомен.com>`),
   `OWNER_EMAIL` (куда присылать сообщения с формы).

Без почты: ключ покупатель всё равно видит на экране, сообщения — в админке.

---

## 7. Свой домен

Vercel → Settings → Domains → добавьте домен → пропишите DNS у регистратора.
Затем задайте `NEXT_PUBLIC_SITE_URL=https://вашдомен.com`, обновите URL вебхуков у
платёжного провайдера и сделайте Redeploy.

---

## 8. Локальный запуск

```bash
npm install
cp .env.example .env.local
npm run dev
```

Открыть: http://localhost:3000. Проверки перед пушем:

```bash
npm run verify
```

(типы → линтер → тесты → сборка).
